# QA 에디터 사용 가이드

이 문서는 팀원이 Unity 프로젝트에서 QA 에디터를 어떻게 실행하고, 결과를 어떻게 해석하면 되는지 정리한 문서입니다.

QA 에디터는 게임을 직접 플레이하지 않아도 데이터와 씬/프리팹 연결 상태를 빠르게 점검하기 위한 Unity Editor 전용 도구입니다. 게임 로직을 자동으로 수정하는 도구가 아니라, 현재 프로젝트 안에서 문제가 생길 가능성이 있는 부분을 찾아 목록으로 보여주는 검사용 도구입니다.

## 1. 실행 위치

Unity 상단 메뉴에서 실행합니다.

```text
Tools > QA > 1. QA Hub
```

세부 도구를 직접 열 수도 있습니다.

```text
Tools > QA > 2. Data & Connection QA
Tools > QA > 3. Planning QA Dashboard
Tools > QA > 4. Run Build Precheck
```

밸런스 확인 도구는 QA 메뉴가 아니라 Balance 메뉴에 따로 분리되어 있습니다.

```text
Tools > Balance
```

## 2. 기본 사용 순서

1. Unity에서 프로젝트를 엽니다.
2. 상단 메뉴에서 `Tools > QA > 1. QA Hub`를 누릅니다.
3. `Data & Connection QA`를 실행합니다.
4. `전체 검사 실행` 버튼을 누릅니다.
5. 결과를 `Error / Warning / Info` 기준으로 확인합니다.
6. 필요하면 필터로 `기획 데이터`, `개발 연결`, `데이터 입력 대기` 등을 나눠 봅니다.
7. `Select` 버튼을 누르면 문제가 있는 에셋, 프리팹, 씬 위치로 이동합니다.

## 3. 결과 등급 의미

### Error

실행이나 연결에 직접 문제가 될 수 있는 항목입니다.

예시:

- 깨진 Object Reference
- Missing Script
- 필수 매니저 참조 누락
- 버튼 OnClick 연결 누락
- 런타임에서 null이 될 가능성이 높은 참조

Error는 우선 확인 대상입니다.

### Warning

당장 게임이 멈추지는 않지만, 데이터가 부족하거나 QA 기준상 확인이 필요한 항목입니다.

예시:

- 보고서 데이터 일부 미입력
- 특정 직원 조합으로 조회 가능한 보고서 부족
- 기획 데이터가 아직 작성 중이라 발생한 누락
- 값은 존재하지만 기준 범위에서 벗어난 항목

아직 데이터가 전부 입력되지 않은 단계라면 Warning이 많이 뜰 수 있습니다. 이 경우 Warning은 버그라기보다 미입력 데이터 확인 목록에 가깝습니다.

### Info

검사가 정상적으로 수행되었거나, 몇 개의 데이터를 찾았는지 알려주는 정보성 로그입니다.

예시:

- Employee SO 10개 발견
- Report SO 773개 발견
- QA 에디터 정상 실행

## 4. 주요 필터 사용법

### 전체

모든 QA 결과를 한 번에 봅니다. 처음 실행했을 때 전체 상황을 파악할 때 사용합니다.

### 기획 데이터 QA

직원, 보고서, 퀘스트, 프로젝트 같은 기획 데이터가 정상적으로 들어갔는지 확인합니다.

주로 기획자가 확인할 항목입니다.

예시:

- 직원 데이터 누락
- 보고서 조건 누락
- 보고서 조합 부족
- 퀘스트 데이터 누락
- 프로젝트 데이터 기준값 확인

### 개발 연결 QA

씬, 프리팹, 버튼, UI 참조, Missing Script처럼 Unity 연결 상태를 확인합니다.

주로 개발자가 확인할 항목입니다.

예시:

- 씬 안의 필수 매니저 누락
- 프리팹의 깨진 참조
- 버튼 OnClick 메서드 누락
- UI 컴포넌트 참조 누락
- Missing Script

### 데이터 입력 대기

아직 기획 데이터가 덜 들어가서 발생한 항목만 따로 볼 때 사용합니다.

데이터가 미완성인 상태에서 개발 오류와 기획 미입력 항목을 구분하기 위해 사용합니다.

## 5. 동일 유형 묶기

`동일 유형 묶기` 옵션은 같은 종류의 Warning이나 Error가 너무 많이 뜰 때 사용합니다.

예를 들어 보고서 데이터가 아직 덜 들어간 상태에서 같은 유형의 Warning이 수백 개 이상 뜰 수 있습니다. 이때 동일 유형 묶기를 켜면 비슷한 항목을 한 줄로 묶어서 볼 수 있습니다.

추천 사용 상황:

- Warning이 너무 많아서 스크롤이 길어질 때
- 같은 원인의 문제가 반복될 때
- 먼저 큰 문제 유형만 보고 싶을 때

## 6. QA와 Balance 도구의 차이

### QA 도구

```text
Tools > QA
```

데이터와 연결 상태를 검사합니다.

확인하는 것:

- 데이터 누락
- 참조 연결 누락
- Missing Script
- 버튼 연결 오류
- 씬/프리팹 구성 문제

### Balance 도구

```text
Tools > Balance
```

수치 밸런스를 시뮬레이션합니다.

확인하는 것:

- 프로젝트 점수
- 보고서 결과
- 매출 구조
- 직원 성장/피로/퇴사 위험
- 회사 재화 흐름

즉, QA는 “정상 연결/데이터 확인”, Balance는 “수치가 적절한지 확인”하는 도구입니다.

## 7. 권장 확인 순서

작업 후에는 아래 순서로 확인하는 것을 권장합니다.

1. `Tools > QA > 2. Data & Connection QA` 실행
2. `전체 검사 실행`
3. `Error` 먼저 확인
4. `개발 연결 QA` 필터로 씬/프리팹/버튼 문제 확인
5. `기획 데이터 QA` 필터로 데이터 누락 확인
6. Warning이 너무 많으면 `동일 유형 묶기` 활성화
7. 기획 데이터 미입력 항목은 `데이터 입력 대기`로 분리해서 확인
8. 수치 밸런스는 `Tools > Balance`에서 별도로 확인

## 8. 팀 작업 시 주의사항

QA 에디터는 문제를 자동 수정하지 않습니다.

표시된 결과를 보고 다음 중 어떤 유형인지 판단하는 용도입니다.

- 기획 데이터 보완 필요
- 개발 연결 수정 필요
- 아직 데이터 입력 전이라 대기 가능
- 실제 런타임 오류 가능성이 있어 우선 수정 필요

Warning이 많다고 해서 무조건 개발 버그는 아닙니다. 현재 프로젝트처럼 보고서, 대화, 직원 데이터가 계속 추가되는 구조에서는 데이터 미입력으로 인한 Warning이 많이 발생할 수 있습니다.

## 9. 팀원별 추천 사용 방식

### 기획 담당자

주로 확인할 필터:

```text
기획 데이터 QA
데이터 입력 대기
동일 유형 묶기
```

확인할 내용:

- 보고서 데이터가 충분히 들어갔는지
- 특정 직원/특성 조합에서 보고서가 부족하지 않은지
- 퀘스트, 직원, 프로젝트 데이터가 비어 있지 않은지
- 반복적으로 뜨는 데이터 누락 유형이 무엇인지

### 개발 담당자

주로 확인할 필터:

```text
개발 연결 QA
Error
```

확인할 내용:

- 씬에 필수 매니저가 있는지
- 프리팹 참조가 깨지지 않았는지
- 버튼 OnClick이 정상 연결되어 있는지
- Missing Script가 없는지
- UI Presenter/View 참조가 비어 있지 않은지

## 10. 자주 보일 수 있는 상황

### Warning이 너무 많이 뜹니다

데이터가 아직 덜 입력된 상태일 가능성이 큽니다. `동일 유형 묶기`를 켜고, `데이터 입력 대기` 필터로 먼저 확인합니다.

### Pull 후 QA 결과가 달라졌습니다

다른 팀원이 데이터나 프리팹을 수정했을 수 있습니다. 먼저 `데이터 새로고침` 또는 `전체 검사 실행`을 다시 눌러 최신 상태로 확인합니다.

### Select를 눌렀는데 무엇을 봐야 할지 모르겠습니다

선택된 에셋이나 프리팹의 Inspector에서 비어 있는 참조, Missing Script, 비어 있는 텍스트/ID/조건 값을 확인합니다.

### Error가 떴는데 내가 수정해도 되는지 모르겠습니다

기획 데이터 문제인지 개발 연결 문제인지 먼저 필터로 구분합니다. 개발 연결 문제라면 담당 개발자에게 공유하고, 기획 데이터 미입력이라면 데이터 담당자가 보완하면 됩니다.

## 11. 한 줄 요약

QA 에디터는 팀원이 직접 모든 씬과 데이터를 하나씩 열어보지 않아도, 현재 프로젝트의 데이터 누락과 Unity 연결 문제를 빠르게 찾아주는 검사 도구입니다.
